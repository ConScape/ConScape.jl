Getting started

TipHere you will learn

The basics of ConScape: importing data, running basic analyses, and exporting resulting maps.

In this first notebook we demonstrate the basic workflow as presented in van Moorter et al. (2022) to compute the amount of connected habitat and the movement flow in four steps:

  1. Set up ConScape
  2. Data import and RasterStack
  3. Definition of a movement mode
  4. Computation of connected habitat and betweenness measures
  5. Exporting results to disk

Define a RasterStack input

ConScape accepts a RasterStack as input, which is a collection of named raster layers.

These can be the following:

  • steplikelihood : likelihood of movement (required). This maybe calculated from stepcost using the likelihoodfunction passed to Problem.
  • stepcost : cost of movement. This maybe calculated from
    steplikelihood using the costfunction passed to Problem.
  • quality: habitat quality (required, or the below alternatives)
  • sourcequality: source habitat quality if it does not match quality.
  • targetquality: target habitat quality if it does not match quality.

Step 2: Defining a movement mode

ConScape provides RandomisedShortestPath, RandomWalk and LeastCostPath as different modes of movement across the landscape.

Least-cost paths are computed as if organisms have perfect information about landscape, while random walks as if they have no information and move randomly. Randomised Shortest Paths fill the space between them - random movement with some knowledge of the landscape, controlled by the theta parameter.

Before solving any ConScape measures, we must choose a movement mode. Here we use the RandomisedShortestPath, or RSP.

Large values of \(\theta\) may result in numerical instabilities resulting in warning messages, and instead RandomWalk should be considered.

Step 3: Solving Measures

All Measure objects can produce outputs, either spatial, scalar or sparse. To solve them we can pass a single measure, a Tuple or NamedTuple of measures.

Habitat connectivity (functionality) measure

One of the main goals of the ConScape library is the computation of the amount of connected habitat in a landscape. The suitability of habitat is typically evaluated based on the local environmental conditions (both biotic and abiotic).

We have coined the term ‘functional habitat’ to evaluate not only the suitability, but also the functional connectivity of habitat. In other words, functional habitat is habitat that is simultaneously suitable and functionally connected. The ConScape library was developed primarily to facilitate this task. The functionality of a pixel is computed with the function connected_habitat:

Betweenness / MovementFlow

Finally, in addition to computing habitat functionality or amount of connected habitat, the ConScape library also computes the number of paths going through each pixel weighted by the likelihood of the path, which is a node’s ‘betweenness’ in network sciences.

ConScape also computes the betweenness weighted by the qualities of the source and target node of a path (i.e. quality weighted) and weighted by the qualities of source and target and their proximity (i.e. proximity weighted). This last version is closely related to what Bodin2010ranking called the ‘generalized betweenness centrality’ using the least-cost paths.

The quality weighting QualityWeighted() highlights the pixels that are in between high quality pixels:

We can use this function to illustrate the effect of the randomness parameter \(\theta\). By setting the quality of two pixels to one while all others are zero we can visualize the distribution over paths between these two pixels, for instance, two pixels:

We can now over a range of \(\theta\) values show the pixels that are most ‘in-between’ the two focal pixels:

We see that as \(\theta\) becomes larger the path distribution becomes narrowly focused on a single path, i.e. the least-cost path, whereas as \(\theta\) becomes smaller the path distribution becomes more diffuse, i.e. a random walk.

Finally, the weighting QualityAndProximityWeighted() computes the betweenness where paths are weighted by the quality of the source and target, but also by their proximity (\(k_{st}\)). As this is an important betweenness, we define MovementFlow as a shorthand for Betweenness{QualityAndProximityWeighted}.

Quality and proximity weighted betweenness, which we refer to as the ‘movement flow’.

MovementFlow highlights the pixels that are most in-between high-quality pixels that are functionally connected together. This metric is expected to capture best the actual movement flows on the landscape (bodin2010ranking).

Summary

We showed a basic workflow to demonstrate the main functionalities in the ConScape library. Step 1 is data import and the representation of the landscape as a RasterStack. In step 2 we define a MovementMode, and step 3 we compute measures of habitat functionality and betweenness, illustrating the effect of the randomness parameter \(\theta\).
