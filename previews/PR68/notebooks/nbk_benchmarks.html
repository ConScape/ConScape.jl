Allocations with missing data

With missing data in the Raster, allocations will in general be significantly less than if all pixels have qualities and affinities. However, there are a few caveats to this statement.

ConScape operates on strongly connected subgraphs, and if parts of the raster are not at all connected, they are split into separate GridInit objects. Overall this improves performance, but with very many tiny subgraphs there will be some memory overhead from initialisation.

Here we benchmark initialisation for a range of sparsities, with non-natural distribution of missing data.

10-element Vector{Int64}:
    1
    1
    1
    4

  148
  876

 1878

We can see that final allocated size decrease with the sparsity of the data, but intermediate allocations spike as the number of disconnected subgraphs increases. It is unlikely that real data will have anywhere near this many subgraphs, as missing data is not evenly distributed, but patchy.
